## 📱 4. Android Device Deployment Instructions

Three options documented for running the app on physical Android devices:
1. **Option 1: Instant Run via Expo Go (~90 Seconds):**
   * Install **Expo Go** from Google Play Store.
   * Connect phone to Mac's Wi-Fi network (Mac IP: `10.81.150.1`).
   * Run `cd apps/mobile && npx expo start` (or `npx expo start --tunnel` for remote testing).
   * Scan the terminal QR code in Expo Go for native execution with biometrics and haptics.
2. **Option 2: Standalone `.apk` File via EAS Build:**
   * Run `cd apps/mobile && npx eas-cli build --platform android --profile preview`.
   * Downloads installable `suraksha-mobile.apk` for permanent distribution to beta testers.
3. **Option 3: Direct USB Cable Native Compilation & Install (`npx expo run:android`):**
   * Connect Android phone via USB and enable USB Debugging in Developer Options.
   * Configure environment: `export ANDROID_HOME=/Users/dpcubed/Library/Android/sdk && export PATH=$PATH:$ANDROID_HOME/platform-tools`.
   * Compile and push directly: `npx expo run:android`.
4. **Option 4: Instant Progressive Web App (PWA) via Chrome:**
   * Start server at port 8000: `uv run uvicorn services.api.main:app --host 0.0.0.0 --port 8000`.
   * Open `http://10.81.150.1:8000` in mobile Chrome and tap **"Install app"**.

## 🔧 5. Android USB Cable Native Build & Prebuild Asset Resolution

### Problem Encountered
When running `npx expo run:android` for direct USB cable deployment, the prebuild step aborted with:
```text
Error: [android.dangerous]: withAndroidDangerousBaseMod: ENOENT: no such file or directory, open './assets/adaptive-icon.png'
```

### Root Cause Analysis
In [`apps/mobile/app.json`](apps/mobile/app.json), the project declared paths for Android icons and splash assets (`./assets/adaptive-icon.png`, `./assets/icon.png`, `./assets/splash.png`, and `./assets/favicon.png`). However, the `assets/` directory was missing from disk, causing Expo's `@expo/prebuild-config` icon generator plugin to crash when calculating image hashes.

### Resolution & Native Generation
1. **Asset Generation:** Programmatically generated full-specification PNG assets matching Suraksha's dark theme (`#090d16`) and identity shield motif via Python Pillow:
   * [`apps/mobile/assets/adaptive-icon.png`](apps/mobile/assets/adaptive-icon.png): 1024x1024 foreground adaptive icon with blue security shield and white verification emblem.
   * [`apps/mobile/assets/icon.png`](apps/mobile/assets/icon.png): 1024x1024 master app icon.
   * [`apps/mobile/assets/splash.png`](apps/mobile/assets/splash.png): 1024x1024 centered splash screen.
   * [`apps/mobile/assets/favicon.png`](apps/mobile/assets/favicon.png): 48x48 web browser favicon.
2. **Native Android Regeneration:** Ran `npx expo prebuild` to cleanly generate the native Android project directory structure in [`apps/mobile/android/`](apps/mobile/android/), including:
   * Gradle 8.8 wrapper (`gradlew`, `gradlew.bat`)
   * Root `build.gradle` and `settings.gradle`
   * App module `build.gradle` with Android SDK 34 targets and biometric permissions (`USE_BIOMETRIC`, `USE_FINGERPRINT`, `VIBRATE`)
   * Android resource densities (`mipmap-mdpi`, `mipmap-hdpi`, `mipmap-xhdpi`, `mipmap-xxhdpi`, `mipmap-xxxhdpi`).
3. **Environment Hook:** Hooked the local Android SDK (`/Users/dpcubed/Library/Android/sdk`) and platform tools into `ANDROID_HOME`, allowing instant USB cable installation.
