### Phase 1: Edge AI, Zero-Backend Architecture & Threat Modeling
**User Requests:**
- *"are these 3 pillars implemented in the code? can we use any of the edge ai techniques here? I am wondering how AI can help here"*
- *"Is there a way we can completetly eliminate the backend server. Let's evaluate this option. If feasible, we should take this approach"*
- *"do we need minisky now to test, now that we have changed the architecture? we also have to be clear on what models are being used in the edge ai architecture we will have to train the model probably"*
- *"how is aadhar tracked if we don't have any backend server?"*

1. **Edge AI & Zero-Backend Architecture Assessment:**
   - **Eliminating Centralized Servers:** By law (DPDP Act 2023 & UIDAI Regulations), collecting and storing citizen identity documents in a central cloud creates catastrophic legal liability and honey-pot risk. Moving all compute to the resident's device ensures zero plaintexts ever leave the device.
   - **Edge AI Model Selection:**
     - *DLP & Content Moderation:* MobileBERT / DistilBERT quantized to INT8 (~15MB–25MB) via ONNX Runtime / CoreML / TFLite to detect context (e.g., distinguishing between an actual Aadhaar share vs a casual reference).
     - *Mathematical Validation:* Pure mathematical Verhoeff Dihedral D5 algorithm running deterministically in microseconds with zero neural network hallucination risk.
     - *OCR & Document Detection:* Apple Vision framework (iOS) and Google ML Kit (Android) for on-device document perimeter detection and number extraction without cloud uploads.
   - **Eliminating MiniSky GCP Dependency:**
     - With the transition to local-first client processing, MiniSky (GCP Firestore/PubSub/KMS emulator) is decoupled from the resident app runtime, enabling instantaneous offline testing and sub-second cold starts.
   - **Tracking Aadhaar Without a Backend:**
     - The device computes a local `HMAC-SHA256(tenant_key, raw_aadhaar)` blind index.
     - The mobile client periodically pulls public darkweb leak hash dictionaries or compact Bloom filters (e.g. from HaveIBeenPwned or threat intelligence repositories) to the device.
     - Membership check occurs entirely inside local SQLite/WatermelonDB memory. The query never reveals what document is being queried.
